# 未着手アイデアバックログ (IDEA_BACKLOG.md)

このファイルは、会話中に出たフリーアイデア・AI提案アイデア・未昇格アイデアのメモ置き場です。

**ドキュメント役割分担**
- `docs/FEATURE_INVENTORY.md`: ROADMAP由来の全量棚卸し
- `docs/IDEA_BACKLOG.md`: このファイル。会話由来の自由アイデア・AI提案アイデア・未昇格アイデア
- `docs/ROADMAP.md`: 正式な優先順位と進捗管理
- `docs/PROJECT_SPEC.md`: 正式な現在仕様

**運用ポリシー**
- 状態ラベルは仮であり、実装順序を確定しません
- 良さそうなアイデアは後で ROADMAP / FEATURE_INVENTORY に昇格します
- 棚卸し時はまず `FEATURE_INVENTORY.md` を確認し、重複を避けてください
- アイデアが実装済みになったら「状態」を更新し、関連docsへのリンクも更新してください

---

## 使い方

- 状態ラベルは次の6種で統一します。
  `未着手` / `一部実装` / `実装済み` / `保留` / `要設計` / `後続拡張`
- `優先度` や `区分` は補助ラベルとして任意に付けることができます。
- 詳細は、可能な範囲で次を記録します。
  アイデア名 / 状態 / 概要 / 実現済みの部分 / 未実装の部分 / 必要になりそうな基盤 / 関連docs / 次に切るならどんなMVP

## 要注意 埋もれやすいアイデア

### ランキング / トレンド / 指標系

- アイデア名: ランキング / トレンド / 指標系。今遊ばれているゲーム、人気ゲーム、新作ゲームの人気度、プレイ数、再利用されているアセット、アセットのお気に入り数、閲覧数、使用数、人気度。作者向けダッシュボード内での表示。
- 状態: `一部実装`
- 概要: カウント系の土台はあるが、ランキング提供や期間指定、分析UIは未整備。
- 実現済みの部分:
  - `GameProject.viewCount` / `playCount` は実装済み
  - 公開ゲーム詳細/プレイ時のカウント MVP は実装済み
  - アセット `favoriteCount` 表示MVP は実装済み
  - `GameAssetReference` / `GameCharacterReference` は実装済み
  - トップページの新着コンテンツ MVP は実装済み（ランキングではなく）
- 未実装の部分:
  - 人気度 / プレイ数 / お気に入り数 / 使用数 ランキング
  - ランキングAPI
  - 「今遊ばれている」など期間指定
  - 「今使われているアセット」表示
  - ユニークな閲覧/ユニークなプレイ
  - イベントログ
  - 日別集計
  - 作者向けダッシュボード
  - 不正/連打対策
- 必要になりそうな基盤:
  - 集計期間定義
  - event log / play session / view session
  - 使用数の定義（公開ゲームのみか、下書きも含めるか）
  - Like / Shelf 分離後の指標定義
  - キャッシュ/集計バッチの要否
- 関連docs:
  - `docs/ROADMAP.md`
  - `docs/PROJECT_SPEC.md`
- 次に切るならどんなMVP:
  - `公開ゲーム 人気度/プレイ数 ランキング MVP`
  - `アセット使用数 usedInGameCount 定義MVP`
  - `ランキング集計基盤 設計メモMVP`
  - ただし本格ランキングは焦らず、まず定義を固める

## M. 長期構想 / 超長期アイデア

### キャラと会話する機能 / 公式キャラクターチャット

- 状態: `要設計`
- 優先度: 極めて低い（本構想の方向性確認後、他の大規模機能追加時に検討）
- 区分: 超長期構想

**発想のルート**:
- Talkingの原点は「ノベルゲームのキャラクターと会話したい」という発想にある。
- ゲーム本編のシナリオ、キャラクター設定、台詞、選択肢、二次創作ゲームなどから、そのキャラらしい会話パターン/語彙を集められる可能性がある。
- 作者が許可した範囲で公式キャラクターチャットを提供できれば、一般的なグレーな版権キャラ再現AIよりも、権利的・体験的に優位性があるかもしれない。

**基本概要**:
- Talkingで作者が作成・公開したキャラクターと、ゲーム外またはゲーム内でAIチャットのように会話できる機能。
- 一般的な版権キャラAIチャットではなく、作者の公式許可下での「Talking上の公式キャラクター」を前提とする。
- 作者が設定を提供し、プロンプト・人格・制限を持ち込めることが重要。

**既存機能との接続**:
- Character / CharacterImage / GameProject / Node / Choice
- GameCharacterReference（キャラが登場するゲーム）
- クレジット / 二次創作 / キャラクター利用許可
- プロフィール / 作者ダッシュボード
- Like / Shelf / Adoption（キャラの利用・支持度）
- AI向けMarkdown/DSL（シナリオExport）
- コメント/レビュー / フィードバック
- 作者による会話ログ確認/採用

**未実装の重要検討項目**:

1. **キャラクター側の準備**
   - キャラ設定の構造化（名前、性格、背景、口調、知識範囲など）
   - 公式台詞データの抽出・整理（ゲーム本編からの自動抽出の仕様）
   - 台詞と地の文、他キャラ発話との区別
   - GameCharacterReference と台詞の紐付け

2. **権利・利用許可モデル**
   - 作者によるキャラチャット許可/不許可の設定
   - 二次創作由来データ（ファンゲーム内の台詞など）を学習/参照に使うかどうかの明示的許諾モデル
   - キャラクターチャットの著作権・責任の整理を利用規約に明記
   - 二次創作者からの許諾取得フロー（可能性）

3. **AI・会話データ処理**
   - RAG（検索拡張生成）設計：公式台詞、キャラプロフィール、関連ゲーム設定をコンテキストとして活用
   - キャラ設定とプロンプト・人格設定の紐付け
   - AI出力へのコスト管理（API呼び出し数、トークン数）
   - プロンプトインジェクション対策

4. **品質・安全性**
   - キャラ崩壊対策（設定と矛盾する発話の抑止）
   - NGワード / センシティブ制御（暴力、性表現など作者許可した範囲）
   - 出力に対する責任明記（AI出力は「キャラになりきったAI」であることを表示）
   - 公開/非公開、二次創作との区別をユーザーに明示

5. **プライバシー・ログ管理**
   - ユーザーとの会話ログの保存・削除方法
   - ログへのアクセス（ユーザー本人 / 作者 / プロモーション目的）
   - 学習データとしての再利用可否と明示的同意

**必要基盤**:
- キャラプロフィール/設定の構造化エンジン（Prismaスキーマ拡張）
- ゲーム本編からの台詞自動抽出またはセミオートアノテーション
- キャラ台詞と発話者の紐付けデータベース
- 作者許諾モデルと利用規約の法的検証
- RAG エンジン（ベクトル検索、LLM API連携）
- キャラチャット設定管理UI（作者向け）
- チャットコンテキスト管理（会話履歴、セッション）
- モデレーション・フィルタリング設定
- AI API のコスト管理（キューイング）

**次に切るなら（段階的アプローチ）**:
1. `キャラ会話構想メモMVP`: 本構想の意義・制約をドキュメント化。利用規約・権利面の整理方針をまとめる。
2. `キャラクター設定構造化MVP`: Character エンティティに設定フィールド（personality, knowledgeRange, speakingStyle など）を追加。
3. `キャラ台詞抽出 設計メモMVP`: ゲーム本編からの台詞抽出方法・フォーマットを設計。
4. `作者許諾モデル 設計メモMVP`: 利用規約、キャラチャット許可フロー、二次創作由来データ扱いの設計。
5. `キャラチャット RAG 基盤MVP`: 公開キャラクターに対して、シンプルな RAG（台詞検索）+ LLM を実装。

**重要な注記**:
- 実装優先度はかなり後回し。いきなり実装しない。
- バージョン管理（Talking v2-v3 段階への構想）。
- 版権キャラの無断再現は扱わず、Talking上の作者が権利を持つ、許可したキャラクターを前提にする。
- 二次創作由来の会話データ利用は、明示的許諾とクレジット/権利設計が必須。
- 「AIがキャラらしく話す」だけでなく、作者がコントロールできることが重要。
- 安全性・法的リスク評価を十分に行う。
- ユーザーが「これはAIである」「作者によるキャラクター解釈である」ことを十分認識できる表示・説明が必須。

**未実装**:

- 参照素材 / 参照キャラクターの解決
